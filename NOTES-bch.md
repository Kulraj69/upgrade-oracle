# BCH edition implementation notes

Snapshot/review date: 2026-10-27. Work performed locally for TASK-bch.md. No push, deployment, submission, mainnet key or mainnet transaction.

## Working locally

- Contract Doctor is the default home view, with the original night/CRT design. No API key or network fetch is needed for its analysis.
- cashc/CashScript 0.14.0 compilation in a worker: 20 KB source cap, five-second deadline, 128 MB heap and in-memory-only import resolution.
- Six evidence-backed rules: P2SH output construction; NFT commitment bounds; loops; reusable functions; unlocking bytecode assumptions; proposed Faster Blocks timelocks. Quotes are exact substrings of SHA-256-checked snapshots and pass the existing citation checker. Source/line matches exclude comments and literals.
- Three real deterministic report fixtures, generated by compiling the included contracts: RecurringPayment 37 bytes / one finding; OutputCovenant 19 bytes / three findings; TokenVault 26 bytes / one finding. Sizes exclude constructor pushes.
- Native loop and reusable function syntax is compiler-tested. Small functions can be inlined; neither opcodes nor savings are promised merely from a source refactor.
- Wallet connection by WizardConnect QR; receive address derived from its xpub; chipnet default; explicit mainnet acknowledgement. One receive index at a time, no whole-wallet discovery.
- Plain BCH input selection, vout-0 genesis selection, optional prep self-send, immutable NFT, 66-byte report commitment, optional 1,000 satoshi fee output and change. Token-bearing/coinbase UTXOs are excluded.
- The actual encrypted localhost WizardConnect handshake and signing round trip passed using `@wizardconnect/wallet` with a runtime testnet key. The signed immutable-NFT transaction passed libauth's BCH 2026 VM. The UTXOs for that test are fake; its transaction ID is not an on-chain result.
- `/seal/[txid]?net=chipnet` decodes the transaction and commitment. Report file comparison is entirely local and checks both hashes plus ruleset and flags. Genesis shape is required; ordinary NFT transfers are not labeled original seals.
- The dependency engine remains at `/dependencies`. BCH presets are visible only when the optional model is enabled. No BCH dependency recording was made, no model call was purchased, and no output was invented.

These results do not establish that the public services are globally down. Network paths from another host may work. Funded genesis, prep-self-send broadcast, actual confirmation lookup and compatibility with a production wallet still need live chipnet testing. The server checks raw transaction hashes and VM validity, but Electrum chain status is trusted; SPV proofs are not implemented.

## SDK findings and patches

- libauth is explicitly pinned to 3.1.0-next.8 for its BCH 2026 VM. Stable 3.0.0 is not the correct validation target for these 66-byte commitments.
- WizardConnect's native request TypeScript types are not its wire format. Its relay invokes `JSON.stringify` directly; the integration uses the provided `sourceOutputToRelay` helper and encoded transaction hex, and the fake wallet decodes using the provided helpers.
- `@wizardconnect/core` 0.2.5 logs network activity by default, including key fragments. Its logging shim is patched to no-ops, and network logging defaults off.
- `@wizardconnect/dapp` 0.2.2 logs malformed session contents; its errors are patched to fixed text without session/key values.
- `@wizardconnect/react` 0.2.3 waits for a courtesy disconnect even before a wallet pairs. When a relay is unavailable, that promise can keep the QR open indefinitely. The patch skips it for unpaired sessions, bounds it to 1.5 seconds for paired sessions, and destroys the old manager. The QR portal also gains dialog semantics, Escape handling and a keyboard focus trap.
- All patches are checked in under `patches/`, applied by the install script, and preserve upstream licenses. Revisit them when upgrading the SDKs.

## Scope and caveats

- Compile measurements and bytecode hashes refer to templates; this UI does not request constructor arguments or deploy contracts.
- Repetition detection is lexical. Findings suggest manual review; this is not a security audit, optimizer or assurance that an unflagged contract is safe.
- Snapshots also include bitwise and OP_SIGHASH, but no speculative rule was added for them. Faster Blocks is explicitly proposed as of the pinned source; no activation or lock-in is asserted.
- A seal commits a particular report, not the author's identity, an endorsement or the truth of its conclusions. Keep the report JSON; only hashes go on chain.
- A configured service-fee address must match the selected network. Users cannot continue on a different network until that configuration is appropriate.
- Source is sent to the compilation server, held in memory and returned in the report. It is not persisted by the app. Do not paste secrets into a contract.
- Compiler concurrency is capped per process, not globally across instances. Electrum requests use fixed hosts and timeouts; a public deployment needs operational rate limits and live-server availability checks.
- The development server hit this workspace's OS file-watch limit. The production build/server was used for browser verification.
